## 本轮选择：以聊天为首页，文件与审阅按需打开

玩家通常用一句话交代建筑要求，随后看 Agent 的进度和世界里的预览。按 `O` 应先看到当前会话，光标在聊天输入框。文件仍有固定入口，点两次可打开任意 TOML。以下是 B+C 讨论稿，尺寸均为 Minecraft **GUI 逻辑像素**。

### 从任务走一遍

1. **发起任务**。左侧停靠聊天面板，顶部一行显示项目名、会话切换和「更多」，第二行只有「对话」「文件」「审阅」。输入框上方显示当前工具和耗时，运行时显示「停止」。继续输入会排队，队列出现在输入框上方。空闲时收起运行行。
2. **查看建造进展**。右侧保留世界画面；可以把聊天暂时收成窄条，按 `O` 返回同一会话。打开 Screen 时鼠标属于界面；要转身、走近建筑，先关闭面板，运行与草稿继续保留。窗口重新打开时恢复原滚动位置。
3. **收到三个待审文件**。聊天中出现一张卡片，列出文件名、估算改动方块数和校验警告。卡片在原位置更新，新卡片不会抢走正在打字的焦点。点文件名或「看差异」进入审阅，同一个文件保持选中。待审角标从真实的服务端状态计算。
4. **逐个决定**。审阅页显示当前文件、上一个/下一个、警告、文本差异和底部「应用」「丢弃」。丢弃原因在当前按钮上方展开；回执到达后再移动到下一个文件。已有世界预览可通过收起面板查看。批量操作显示文件数量，遇到旧版本或单文件失败保留失败项和原因。回到对话仍在刚才那张卡片。
5. **偶尔手改**。点「文件」进入列表，选文件先看正文，再点「编辑」。编辑时用完整页宽；窄屏用「返回文件列表」返回同一路径。保存、撤销编辑与应用建筑是独立操作。编辑草稿未保存时离开可选择保留或放弃。计划、检查点、撤销/重做和诊断导出放入「更多」，审阅工作流无需经过这个菜单。

### 审阅与文件共用同一块面板

```text
┌ 对话    文件    [审阅 3]       展开 ┐
│ ‹ 1/3 ›   大厅.toml    418 方块     │
│ ⚠ 东侧入口与拱门重叠；查看详情      │
│ − 原来的门框……                     │

└────────────────────────────────────┘
```

同一时间只显示一个主视图。手动「展开」可把面板拉到全屏，宽屏审阅才考虑并排差异；默认采用逐行差异，使窄屏也能完整读一行。返回对话保留输入草稿、文件光标、未处理的审阅选择。Esc 先关内层菜单或原因框，再退回对话，最后关面板。

| 逻辑窗口 | 讨论稿尺寸与降级 | 实机验收 |
|---|---|---|
| 640×360（例如 1920×1080、缩放 3） | 默认面板 352 宽，余下 288 给世界；顶栏 22、标签 20、输入 24、运行行最多 20 | 能一眼看到第一条请求、审阅卡和发送入口；世界预览仍可辨认 |
| 480×270（缩放 4） | 默认面板 288 宽、世界 192；项目名截断，次要动作进「更多」；长文件名允许换行 | 在中英文下逐个处理三个文件，输入和审批按钮均不被遮住 |
| 320×240 或更窄 | 整个界面切单栏；文件列表和正文分页，顶栏只留返回、标题、更多 | 用键盘切换文件、取消丢弃、回到原草稿，焦点与滚动位置正确 |

### 主题独立于布局

建议在 `config/p2s_themes/` 放多个独立 JSON，通过「更多 → 外观」选择并即时预览，提供一键恢复。主题只定义背景及透明度、正文、弱化文字、焦点边框、警告与差异颜色，以及字体阴影和间距档位。内置深蓝和高对比两套即可比较。改主题时保留当前面板、滚动位置、输入草稿和审阅文件。坏文件标出主题名和无效字段，继续用上次可用主题。操作语义、快捷键和断点属于布局，切色时不会移动文件入口。对比试验要使用同一个建筑、同一个缩放档位，在雪地和夜景各看一次。

**下一轮只需要决定两件事**。默认给世界留多少空间（640 宽时先试 288），以及点待审卡时优先保留世界画面还是自动放大文本差异。前者影响常驻面板宽度，后者影响进入审阅的方式；其余快捷键和颜色可等首次游戏截图后调整。

## 0. 一句话结论

界面功能齐全，但三件事拖后腿：
1. **布局全靠手写像素**，GUI 缩放调到 3、4 档或窗口变小时，按钮会重叠、编辑区只剩几行。
2. **新 Agent 功能几乎没有界面**：运行中、排队、多文件审阅、脚本子调用、思考文本、子 Agent 进度，目前要么只有一行灰字，要么完全看不到。还有一个现成的 bug：多文件“全部应用”的提示挂在一个永远为空的按钮上，玩家看不到。
3. **两套视觉风格混用**：右侧会话面板用原版石头按钮，左侧用自绘扁平按钮，配色各写各的。

建议先做第 3 节的“快速修复”（1～2 天，风险低），再做“运行状态条 + 审阅条 + 工具日志树”这一组中等改动，最后再考虑拆分 4900 行的 `P2SChatScreen`。

### 1.3 具体问题（按类别，附位置）

**A. 布局挤压与重叠（GUI 缩放越大越明显）**

以下按 1920×1080、GUI 缩放 4（逻辑尺寸 480×270）估算，3 档（640×360）也有部分问题。

1. **会话面板第一行按钮重叠。** 左边“项目/会话/新建/[i]”占到 `panelX+212`，右边“压缩”从 `panelX+W-132` 开始（`P2SChatSessionWidgets.java:136-165`）。面板取最小宽 320 时，二者重叠约 24px。逻辑宽度 ≤ 800（即 1080p 下缩放 ≥3）时面板就会落到最小宽。
2. **顶部三行按钮只放了 8 个按钮，却吃掉约 94px 高。** 第 2 行左半空着（只有右侧撤销/重做），第 3 行只有“存点/列表”（`:167-185`）；`getHeaderHeight` 至少 `20*3+8+14`（`P2SChatScreen.java:4238-4259`）。在 270 高的屏幕上，消息区只剩约 130px，十来行字。
3. **丢弃原因输入框出现时，消息区会跳动。** 它放在会话面板第 4 行（`P2SChatSessionWidgets.java:242-258`），可见时 `getHeaderHeight` 会把它算进去，消息区上沿下移。
4. **点左边的“丢弃”，原因输入框却出现在最右边。** “丢弃”按钮在左侧编辑区（`P2SChatContextWidgets.java:313-322`），原因框在右侧会话面板。如果会话面板折叠，`discardReasonInput` 为空，进入丢弃模式后左侧“应用/丢弃”会被隐藏（`P2SChatScreen.java:3175-3182`），界面上没有可见的确认入口（需实机确认能否用 Esc 退出）。
5. **输入框右侧永远空着约 56px。** 输入框宽度按“Ask”按钮存在来算（`P2SChatSessionWidgets.java:112-113`），但该按钮只在有待选项时才显示。
6. **编辑区在小屏上只有 4～5 行。** 编辑区底部固定预留 110px 给“附带上下文”列表（`CONTEXT_FOOTER_HEIGHT`，`P2SChatScreen.java:48`），每行 18+2px（字体只有 9px 高）。270 高时可视行数约 5（`P2SChatContextWidgets.java:351-355`）。
7. **配置页 LLM Tab 在缩放 ≥3 时放不下。** 内容起点约 `h/10+36`，往下还有 7×50px 加提示和系统提示，没有滚动；横向需要约 610px（`P2SConfigScreen.java:219-246`）。
8. **会话列表固定 10 行**，顶部 40 + 10×24 + 底部按钮约 310px，比 270 还高（`P2SSessionListScreen.java:20,58,85`）。

**B. 写死的像素和颜色**

- 布局常量散落在三个文件里：`P2SChatScreen.java:34-70` 有 30 多个常量，组件类里还有 `64/44/56/64/42` 这类裸数字（`P2SChatSessionWidgets.java:139-185`），`P2SChatContextWidgets.java:121-127` 又写死 `24`、`28`。
- 颜色直接写在调用处，`P2SChatScreen` 里有 92 个不同的颜色值。同一种“分隔线”有 `0xFF2F3A4D`、`0x6637465E`、`0xAA324153` 三种写法（`:3315`、`:3496`、`:3387`）。
- Info 浮层的 `[X]` 关闭位置在绘制和点击里各算一遍（`:3853-3854` 与 `mouseClicked` 内同样的公式），改一处另一处就错位。

**C. 风格不一致**

- 右侧原版石头按钮 vs 左侧深蓝扁平按钮，同一屏两种风格。
- 右侧背景纯黑半透明 `0xAA000000`（`:3272`），左侧偏蓝 `0xC0141A26`（`:3314`），折叠条又是另外两种颜色（`:3556-3567`）。
- 聊天文字用的是原版聊天色：用户白、AI 亮绿 `0x55FF55`、系统灰 `0xAAAAAA`（`:4733-4744`），和其余蓝灰配色不搭；流式输出也是亮绿（`:4009`）。
- 两个多行编辑器：上下文编辑器手写在 `P2SChatScreen`（光标、选区、复制粘贴约 800 行，`:1953-2760`），技能编辑器用 `P2SMultiLineTextEditor`。行为（快捷键、滚动、配色）不一致，修 bug 要修两遍。

**D. 反馈和可发现性不足**

- **“全部应用”提示是死代码。** `render()` 给 `applyButton` 设置“N 个文件有暂存改动，按住 Shift 全部应用”的提示（`P2SChatScreen.java:3197-3203`），但 `applyButton` 永远是 null：会话组件构建时就传了 null（`P2SChatSessionWidgets.java:266`）。真正的“应用”按钮是左侧的 `contextApplyButton`，它没有提示。所以 Shift+应用 这个功能玩家完全无从得知。
- 符号按钮没有任何提示：`<`、`>`（折叠）、`<D`、`D>`（跳到上/下一处差异）、`[i]`、`X`、`×`、`>`（发送）。全项目只有两处 `setTooltip`（`:3201`、`:3210`）。
- 资源管理器里待审文件的角标是 `M12`（`:1197-1202`），没有说明 M 是什么、12 是改动方块数。
- 消息区没有滚动条、没有“有新消息”提示；向上翻看历史时，新消息到来不会提醒。
- 状态只有一行灰字“状态：思考中”（`:3972-3979`），没有动效、没有耗时，Agent 卡住和正在干活看起来一样。
- 工具执行期间看不到“正在执行什么”：工具日志只在 `ToolExecutionEnd` 时才加一条（`ClientAgentManager.java:589-603`）。

**E. 无障碍与键盘**

- 扁平按钮的禁用文字 `0x7B8CA6` 画在 `0x55…` 半透明底上（`P2SFlatButton.java:33`、`:57-63`），背后是游戏画面，在雪地、沙漠这类亮场景里对比度可能很差（需实机确认）。
- 大量文字不带阴影（`drawString(..., false)`），同样受背景亮度影响。
- 键盘：有 Tab 切换折叠面板焦点、Enter/Esc 处理（`:2762-2875`），但没有发送以外的快捷键（例如应用、丢弃、停止、打开 Info）。扁平按钮的焦点框和悬停共用同一效果，键盘焦点不明显。
- `zh_cn` 中 `screen.p2s.chat.choice.ask` 仍是英文 “Ask”（`zh_cn.json:339`）。其余语言键两边齐全（375 对 375，代码里用到的键都有定义）。
- v2 工具（`ls/read/grep/edit/write/script/sh/task...`）没有摘要翻译，日志标题直接显示英文工具名（`ClientAgentManager.java:1279-1304` 的 switch 只覆盖旧工具名）。

**F. 每帧开销**

- 消息区每帧把全部消息（最多 200 条，`ClientSessionState.java:362`）复制一遍并用 `font.split` 重新折行，而且做两遍：`computeContentHeight` 一次、`drawMessages` 又一次（`P2SChatScreen.java:3988-3993`、`:4028-4044`）。流式输出时整段文字每帧也折行两次。
- 每帧 `countInfoSections` 生成 5 组折行文本只为数个数（`:3283-3296`、`:3827-3835`），打开 Info 时又生成一遍。
- 附带上下文列表每帧折行（`:3347`）。
- 其余：`getMessages()` 每次加锁并复制列表（`ClientSessionState.java:416-418`）。
- 消息少时无感，长会话 + 大量工具日志时可能掉帧（需实机用 F3 看帧时间）。
- 其他界面：项目/会话/检查点/配置/技能编辑在 `render()` 里先调 `super.renderBackground` 再调 `super.render`（例：`P2SProjectListScreen.java:573-574`）。1.21 的 `Screen.render` 自己也会画背景，等于模糊两次（需实机确认观感）。

**G. 安全相关的小问题**

- 配置页 API Key 明文显示（`P2SConfigScreen.java:178-181`），直播或截图时会泄露。

## 2. 新 Agent 功能在界面上的缺口

| 功能 | 现在怎么显示 | 问题 |
|---|---|---|
| 运行中 / 停止 | 发送键在“运行中且输入为空”时变成 `■`（`P2SChatScreen.java:3205-3212`、`:4807-4818`），停止后加一条系统消息 | 只有一个 22px 的小方块；输入框里有字时就看不到停止按钮；“正在停止”没有过渡态 |

| 思考文本 | 解析到 `ThinkingDelta`（`OpenAiChatCompletions.java:218,361`），`onAgentEvent` 只处理 `TextDelta`（`ClientAgentManager.java:570-572`），直接丢弃 | 推理模型长时间思考时，玩家只看到“思考中”且不知道进度 |

### 3.2 中等改动（新功能的界面）

**M1. 运行状态条（替代单行状态文字）** — M，中风险
- 问题：运行/停止/排队都没有明确表现（第 2 节）。
- 改法：消息区与输入框之间放一条固定高度 12～14px 的状态条，只在会话活动时出现：
  ```
  ┌──────────────────────────────────────────────────────┐
  │ ⟳ 运行中 · 第3步 · 正在执行：运行脚本 · 0:42   [停止] │
  │ 排队 2 条：「把屋顶改成…」「顺便加窗」          [撤回] │
  └──────────────────────────────────────────────────────┘
  [输入框.................................] [发送]
  ```
  - 转圈符号用 `⟳ ◐ ◓ ◑ ◒` 按时间轮换，不需要贴图。
  - “停止”是独立按钮，输入框有字时也能停；点了之后变成灰色“正在停止…”直到结束。

- 验证：发消息后立即再发两条，看排队显示；中途点停止，状态条依次显示“正在停止”“已停止”；无排队时状态条不占位。

**M2. 审阅条（多文件暂存）** — M，中风险
- 问题：一轮改多个文件后，玩家不知道共几个、还剩几个。
- 改法：左侧编辑区顶部、按钮行下方，有待审文件时显示审阅条：

  - 文件名可点，直接跳到该文件的 Diff。
  - “全部丢弃”需要二次确认（同一按钮第二次点击才生效，3 秒内有效）。
  - 风险等级用颜色点表示（沿用 Info 浮层的低/中/高配色，`P2SChatScreen.java:3870-3877`）。
- 验证：3 个文件逐个应用、全部应用、全部丢弃三条路径各走一遍，检查世界方块和 Undo。

**M3. 工具日志树（含脚本子调用）** — M，低～中风险
- 问题：脚本/命令结果里的子调用、耗时、输出全没显示；源码被压成一行。
- 改法：日志标题一行写清结果，展开后分区显示：
  ```
  ┌ ▸ 运行脚本 · 12 次调用 · 1 失败 · 0.8s ───────────── ✗ ┐
  └──────────────────────────────────────────────────────────┘
  ┌ ▾ 运行脚本 · 12 次调用 · 1 失败 · 0.8s ───────────── ✗ ┐
  │ 源码（前 6 行）                                         │
  │   const walls = ws.list("walls/");                      │
  │   ...                                                   │
  │ 子调用                                                  │
  │   ✓ read ×6   ✓ edit ×5   ✗ write: path not allowed     │
  ```

## 5. 读代码判断不了、需要实机看的

- 不同 GUI 缩放下的真实重叠程度（第 1.3-A 的数字是按代码推算）。
- `▸ ▾ • × ■ ⟳ ◐` 这些字符在原版字体里的实际效果（会回退到 Unifont，粗细和大小可能与正文不一致）。
- 半透明背景在亮场景里的文字对比度。
- 其他界面 `render()` 里重复 `renderBackground` 是否确实造成双重模糊。
- 会话面板折叠时点“丢弃”是否会卡在无法确认的状态（1.3-A 第 4 条）。
- 长会话下每帧折行造成的实际帧时间影响。
