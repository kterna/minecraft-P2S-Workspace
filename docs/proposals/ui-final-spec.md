# 游戏内界面最终实现规格

这份文档汇总 2026-11-26 的界面讨论，作为实现依据。三家模型的效果图、文档和对比截图都在 `docs/mockups/` 和 `docs/proposals/ui-layout-*.md`，这里只记录最后的决定。

## 1. 决定一览

| 项目 | 决定 | 来源 |
|---|---|---|
| 视觉风格 | 以 GPT 第二版为准（`docs/mockups/gpt/`） | 用户在三家对比后选定 |
| 主题 | GPT 的 8 套主题，`themes.json` 第 2 版协议，每套 35 个颜色字段；不提供高对比主题 | 用户要求“高级感、优雅感、平滑感”，并否决了高对比 |
| 布局 | 左侧工作台约 300 GUI 像素（窄屏 244），右侧是真实世界；不保留“世界预览”标题栏 | GPT 第二版 |
| 收起面板 | 工作台可以用 `«` 收起成窄条，世界几乎全屏 | 借鉴 Gemini XHigh 版 |
| 世界预览 | **C 方案**：真实世界里画待审方块的半透明虚影，面板打开时相机环绕选区中心（拖动旋转、滚轮缩放、复位），关闭后回到玩家视角 | 用户选定 C |
| 当前文件高亮 | 审阅某个文件时，世界里只高亮这份文件的虚影，其他文件变暗 | 三家都有，Gemini XHigh 版最清楚 |
| 审阅页 | 默认显示人话摘要（材料、占用范围、新增部件、改动方块数、校验警告）；“查看差异”可以展开，默认折叠未改动行 | GPT 第二版 + Gemini XHigh 的折叠差异 |
| 应用后的选择 | **停在刚应用的那份**，由玩家自己点下一份；以后可做成设置项 | 配合 C 方案，玩家应用后通常要先看世界 |
| 右下角物品栏 | 不做（与原版快捷栏重复） | Gemini XHigh 版的问题 |

## 2. 主题系统

- **格式**：与 `docs/mockups/gpt/themes.json` 相同：`{"version": 2, "default": "<id>", "themes": [{"id", "name", "colors": {35 个字段}}]}`。颜色用 `#RRGGBB` 或 `#RRGGBBAA`。
- **35 个字段**：`backdrop inset panel raised line text muted faint accent on-accent hover pressed focus input-bg input-border selected scrollbar success warning danger info diff-add-bg diff-add-text diff-remove-bg diff-remove-text tool-done tool-running tool-waiting tool-failed preview-add preview-remove preview-file overlay on-overlay text-shadow`。
- **来源**：内置 8 套主题放在 mod 资源里；玩家可以在 `config/p2s_themes/` 放额外的 JSON 文件，`id` 相同时以玩家的为准。
- **切换**：在设置界面的“外观”里选择，也可以用 `/p2s theme <id>` 切换、`/p2s theme reload` 重新读取。选中的主题保存在 `p2s_client.json`。切换后立即生效，不重开界面，也不丢输入草稿和滚动位置。
- **出错处理**：文件读不了或字段不合法时，跳过这个文件，并在日志和聊天框里写明文件名和出错字段；当前主题保持不变。缺少的字段用默认主题的同名字段补上。
- **平滑感**：悬停、按下、选中用透明度或亮度插值，过渡大约 100ms，不换颜色。
- **范围**：聊天工作台、设置界面、项目/会话/检查点/技能列表、HUD、扁平按钮和多行编辑器里写死的颜色，全部换成主题字段（目前大约 314 处）。

## 3. 布局（主稿 640×360 GUI 像素）

- 顶栏：P2S 标识 / 项目 / 工作区；右侧是当前主题名和“⋯”菜单（切换会话/项目、撤销/重做、检查点、导出诊断、设置、外观）。
- 标签：对话 / 文件 / 审阅（显示待审数量）。`Alt+1/2/3` 切换。
- 对话：一行会话标题；玩家消息用浅一档的底色；Agent 回复带头像；“工具进度”卡包含思考（字数，可展开）、计划、子 Agent 嵌套、脚本子调用和失败原因；停止按钮放在卡片标题行；排队的消息显示“已排队”，可以撤回；输入框固定在底部。
- 待审卡片：每份文件一行，显示材料图标（用 MC 物品图标）、文件名、中文名和 `+N 方块`；底部是“开始审阅”。
- 文件：左边目录，右边带行号的只读正文；点“编辑文件”才可以改，保存后成为待审改动。
- 底栏：Agent 状态、快捷键提示。
- 面板关闭时：屏幕右上角显示 HUD（运行状态、待审数量）。
- `Esc` 一层层退出：确认框 → 编辑 → 输入框焦点 → 文件/审阅回到对话 → 关闭面板。停止 Agent 只能用“停止”按钮。

## 4. 世界预览（C 方案）

1. **服务端**：暂存改动时已经由 `StructurePatchEngine.diff()` 算出逐个方块的差异。新增一个数据包，把每份待审文件的差异（方块状态编成一张表，坐标只存表里的编号，太大时分包）发给客户端；应用或丢弃后发清除指令。
2. **客户端虚影**：新增的方块半透明显示，要删除的方块用 `preview-remove` 颜色画框，当前审阅的文件用 `preview-file` 描边；其他文件变暗。“仅看已应用”开关可以隐藏所有虚影。
3. **环绕相机**：面板打开、并且有选区或待审文件时，可以切换到环绕视角：拖动旋转、滚轮缩放、复位按钮回到默认角度。相机距离要有上限，避免看到未加载的区块。关闭面板或退出环绕视角后，回到玩家视角。
4. **审阅摘要**：材料、占用范围、新增部件、改动方块数，从同一份差异数据算出来，随数据包一起发送。

## 5. 实施顺序和分工

| 步骤 | 内容 | 谁做 | 分支 |
|---|---|---|---|
| 1 | 主题系统（第 2 节） | GPT（Codex） | `feat/ui-theme`，从 `integration/agent-llm` 拉出 |
| 2 | 世界预览数据包、虚影、环绕相机、审阅摘要（第 4 节） | Claude | `feat/world-preview`，从 `integration/agent-llm` 拉出 |
| 3 | 合并 1、2 到集成分支，构建、跑测试 | Claude | `integration/agent-llm` |
| 4 | 布局骨架（第 3 节）：顶栏、标签、工具进度卡、待审卡片、审阅页、文件页、HUD | 待定 | 基于步骤 3 |
| 5 | 游戏内验收：实际截图，与 HTML 效果图对比 | GPT（用户开着的 Codex 会话） | 只读 |

两个工作树互不重叠：GPT 只在 `p2s-wt-theme` 里改动，Claude 只在 `p2s-wt-preview` 里改动。主题系统需要的颜色字段 `preview-add / preview-remove / preview-file`，世界预览会通过主题接口读取，接口名在第 6 节约定。

## 6. 两条分支之间的接口约定

- 主题读取：`com.p2s.theme.P2STheme.current().color("preview-add")` 返回 ARGB `int`。Claude 在预览分支里先放一个只返回默认颜色的临时实现，合并时以 GPT 的实现为准。
- 主题变更通知：`P2STheme.addListener(Runnable)`，主题切换后调用。
