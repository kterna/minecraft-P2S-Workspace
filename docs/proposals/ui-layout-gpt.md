# 松脊营地 · P2S 游戏内 Agent 工作台

按 `O` 打开后，左手是刚才的对话，右手仍能看见山脊。Agent 做好了屋顶，玩家点一下文件名，就能顺着画面里的标记找到那片屋顶。决定要不要它，比看懂一份 TOML 更重要。

[打开可交互样稿目录](../mockups/gpt/index.html)

## 屏幕上的位置

| 区域 | 640 × 360 主稿 | 玩家在这里做什么 |
| --- | --- | --- |
| 顶栏 | 高 25 px | 确认项目和工作区。右上角显示当前主题，点一下切换。 |
| 左侧工作台 | 宽 358 px，含右边线 | 对话、文件、审阅共用一块地方。对话默认打开，有待审文件时，审阅标签上出现数量。 |
| 右侧世界 | 宽 282 px | 保留相机位置和朝向。看整座塔，也能切到「仅看已应用」，看一眼本轮提案到底加了什么。 |
| 底栏 | 高 14 px | 换页也能看见 Agent 是否在运行。应用结果、队列反馈和返回键提示都在这里。 |

**对话**占据主要位置。玩家原话放在浅一档的底色上，Agent 的回复带头像。工具按调用顺序往下读；每行给出工具名、一句人话和耗时或状态。当前行有箭头和底色，成功打勾，等待用空方框。停止按钮紧跟工具记录，输入栏固定在底部。

**审阅**从对话里的三行文件卡进入，也可从标签直达。上半部保留本轮所有文件和各自的决定，下半部只讲选中的一份：用了什么材料、占多大地方、改了哪些部件。右侧同时画出边界和文件名。最下方的「应用此文件」「丢弃」总对当前这份生效。

**文件**在第二个标签里。打开先看目录和带行号的正文，主动点「编辑文件」才进入编辑。待审正文标为「提案 · 只读」；已应用的文件也能重新打开。「查看 TOML」从审阅直达当前文件，免去再找一次。回到对话时，输入草稿和阅读位置都保留。

## 把一座塔建完

1. **交代任务。** 在样稿画布下点「从发起开始」。西坡选区里还没有建筑，输入框已填好“在山脊上建一座木瞭望塔，要有铜屋顶，再用栈梯接到西坡。”点「发送」。
2. **看它做事。** `inspect_world` 先读地形，`task` 收回屋顶子 Agent 的结果，`script` 计算塔身与栈梯落点，`write` 等待写入 TOML。此时输入“栈梯外侧也要扶手”，按 Enter 会进队列。停止会中断当前运行，草稿、排队消息和已有提案都保留。
3. **收到三份待审文件。** 点画布外的「推进演示：生成完成」。对话里出现 `tower.toml`（塔身）、`roof.toml`（屋顶）、`stairs.toml`（栈梯），每行有材料图标和新增方块数。如有追加消息，Agent 按入队顺序接着读，玩家此时可以去审阅。样稿用手动推进来控制演示时间。
4. **一份一份决定。** 点塔身行，看四根立柱和观景台，选「应用此文件」。计数从 3 变 2，选中项移到屋顶。切一下「仅看已应用」，眼前只剩已建好的塔身；再打开预览，铜顶和栈梯重新出现。应用屋顶后试着丢弃栈梯，确认框会写明文件名。确认后栈梯从山坡消失，两份已应用的文件留在原处。
5. **偶尔改个值。** 切到「文件」选择 `roof.toml`，点「编辑文件」，把 `minecraft:weathered_cut_copper` 换成 `minecraft:cut_copper`。选「保存为待审」回到审阅；预览里的青铜色屋顶变成暖铜色。「应用此文件」才更新已应用的世界，丢弃这次手改会回到原来的青铜顶。

样稿在内存中演示这些决定。独立入口各自从标题所写的状态开始，刷新会重置任务。「文件」入口从建造完成后开始，适合直接试手改。世界是按像素绘制的分层场景，铜材质替换有对应画面；任意脚本、其他 TOML 改动的实际建造结果，要由游戏执行和校验。

## 尺寸、用色和窄屏

主稿按 640 × 360 个 GUI 像素绘制，默认放大两倍到 1280 × 720。标题可以稍大，工具名、文件名和状态用约 9 px 的字，密集状态行的字行高为 9 px，正文多留一点行间距。标签靠底边短线选中，面板用单像素线分隔。材料小图、山脊、树林和塔都能用像素贴图或实色矩形绘制。场景保留游戏自身的光照，只有界面和选区标记跟随主题。

480 × 270 另有独立入口，默认显示为 960 × 540。左栏占 293 px，世界占 187 px，画面从两边裁掉一部分，塔仍在中间。标签和工具行收紧，页脚收掉次要快捷键。长对话和审阅说明在各自区域内滚动，输入、应用和丢弃仍然伸手可及。文件页把双栏压成正文单栏，点「目录」展开覆盖式文件列表，选完自动收回。浏览器窗口小于 760 CSS px 时也使用窄稿，再按可用宽度缩小。

## 键盘与退出

| 操作 | 结果 |
| --- | --- |
| `O` | 打开或收起面板，收起后仍能继续运行。正在输入时字母正常进入文本框。 |
| `Alt+1 / 2 / 3` | 分别切到对话、文件、审阅。离开有修改的编辑器时先处理草稿。 |
| `Tab` / `Shift+Tab` | 顺序或反向移动焦点。按钮用 Enter 或空格触发。确认框先聚焦「返回」。 |
| 消息框内 `Enter` | 空闲时发送，运行中排队。中文输入法选词期间留给输入法处理。 |
| 编辑器内 `Ctrl+S` 或 `⌘S` | 保存为待审，再到审阅页决定是否应用。 |
| `Esc` | 每次退一层。先关确认框，再退出编辑或收起窄屏目录；有未保存修改时可返回继续写。消息框有焦点时先退出输入，文件或审阅页退回对话，对话页再退回游戏。停止运行始终由「停止」触发。 |

## 主题文件

两套配色放在同一份 [themes.json](../mockups/gpt/themes.json)。**余烬**用墨绿底和炉火色强调当前工具、预览边界与主要操作；**冰川**用浅灰蓝底和深青色，在亮处也能读清。状态同时使用图形和文字。

顶层 `version` 当前为 `1`，`default` 指向默认主题的 `id`，`themes` 是主题数组。每套主题有唯一的 `id`、按钮显示的 `name` 和 `colors` 对象。所有颜色都用 `#RRGGBB` 或 `#RRGGBBAA`。以下是完整的一套。

```json
{
  "version": 1,
  "default": "ember",
  "themes": [{
    "id": "ember",
    "name": "余烬",
    "colors": {
      "backdrop": "#181d1c", "panel": "#202725", "raised": "#29312e",
      "inset": "#1b211f", "line": "#404942", "text": "#f0efdf",
      "muted": "#b3b9aa", "faint": "#98a398", "accent": "#ffb767",
      "on-accent": "#251e18", "tint": "#3e372c", "success": "#a7d7b1",
      "danger": "#ffaaa0", "overlay": "#1a221ee8", "on-overlay": "#f1f1df"
    }
  }]
}
```

`colors` 的每个键都对应一个同名 CSS 变量，只在前面加 `--`。例如 `accent` 决定主按钮底色，`on-accent` 决定按钮文字，`overlay` 与 `on-overlay` 控制压在世界上的标签。增加主题时复制一个数组成员，换掉标识、名称和颜色即可。

每份 HTML 都内嵌交付时的同一份 JSON，双击即可离线切换。改过独立 JSON 后，点画布外的「载入主题 JSON」并选择文件，当前页面立即采用其中的默认主题；随后仍可点游戏顶栏轮换。载入时会核对版本、字段和色值，读错时保留当前配色。

## 需要拍板的三个问题

1. 默认用「余烬」还是「冰川」？我倾向余烬，黄铜色运行行和世界里的选区标记能一眼对上。
2. 应用一份文件后，是否自动选下一份？样稿会自动前进；如果玩家经常要转身验收刚放下的方块，可以保留当前选中项。
3. 窄屏是否始终给世界留 187 px？样稿保留这条视野，审屋顶时仍能看到屋檐和栈梯；代价是读长 TOML 时需要横向滚动。
