# 松脊营地 · P2S 游戏内 Agent 工作台

按 `O` 打开工作台。左边读对话、看文件，右边保留对山脊的视线。屋顶换材质时，先看它会变成什么样，再决定是否需要展开那一行 TOML。[打开样稿目录](../mockups/gpt/index.html)

## 画布和操作区

| 区域 | 640 × 360 | 480 × 270 |
| --- | --- | --- |
| 左侧工作台（含边线） | 300 px | 244 px |
| 右侧世界 | 340 px | 236 px |
| 顶栏 / 工作台标签 / 底栏 | 21 / 20 / 13 px | 18 / 17 / 11 px |
| 文件浏览 | 目录与正文并排 | 点「目录」展开覆盖列表，选完收回 |

项目和工作区名留在顶栏。对话里只用一行放会话名和选区尺寸。工具记录、文件正文、审阅详情分别滚动，输入框和审阅操作固定在底部。窄屏默认折起脚本子调用。每份 HTML 可直接在本地打开，默认最大放大两倍。浏览器宽度小于 760 CSS px 时使用窄稿，再按可用宽度缩放。[窄屏样稿](../mockups/gpt/narrow.html)

世界画面从顶栏下缘开始。左上角在「预览开启」和「仅看已应用」之间切换。审阅时，虚线框跟着选中的文件走，局部的加号和叉号标记新增方块和待移除的旧方块。位置和图例靠左下角，右下角给旋转、缩放、复位留位，塔身和屋顶中央可以用于拖动。本轮用像素山景和三层建筑叠画表现预览。右下角是后续 3D 交互的控件位置示意。

## 从对话走到应用

1. **看运行记录。** 「思考」默认收起，显示可展开的示例文本字数。「计划」显示当前步骤和已完成数，点开可看全部三步。工具卡中的 `task` 下缩进一行屋顶子 Agent 结果。`script` 展开后依次显示读取塔身、第一次平移缺少 Z 坐标、补值后重新计算。卡头可停止或继续运行。[运行中](../mockups/gpt/running.html)
2. **追加和撤回。** 运行中按 Enter，消息出现在输入框上方，带「已排队」和独立的「撤回」。点画布外的「推进演示」结束当前步骤，队首随即进入处理。点「从发起开始」可以从空选区重新走一遍。对话中的文件卡可以直接选中一份文件。[待审卡片](../mockups/gpt/pending.html)
3. **先读摘要。** 文件列表保留每份提案的决定，以及该文件的校验警告数。下方先显示选中部件的效果、主要材料、尺寸和构成。有警告时就地列出原因。屋顶样例包含一个空的 `finial` 部件，玩家能在应用前看到它不会放置方块。[逐份审阅](../mockups/gpt/review.html)
4. **按需核对正文。** 「查看差异」默认折起，标题先给增删行数。展开后先读 Agent 的一句说明，再看有底色和正负号的 TOML 行。进入审阅样例时，塔身已经应用，旧屋顶使用 `cut_copper`，提案改为 `weathered_cut_copper`，栈梯仍待审。切换世界预览能直接比两种铜色。新文件从空基线比较，手改已有文件与上次应用的正文比较。
5. **应用或改稿。** 「应用此文件」更新这一份，随后选中下一份待审文件。「丢弃」先显示带文件名的确认框。文件页可以改正文，保存为待审，再回来比较或丢弃。样稿能演示铜材替换。任意 TOML 的完整几何和校验由游戏端处理。[工作区文件](../mockups/gpt/files.html)

游戏顶栏的「⋯」分三组放置会话与项目、撤销与重做及检查点、诊断与设置及外观。单击外侧或按 Esc 收起。样稿提供一个项目和一个会话，审阅决定可以撤销或重做，也能保存和恢复当前工作区检查点。导出诊断生成一份本地 JSON，内容是样稿状态、队列长度和文件状态。[菜单展开态](../mockups/gpt/running.html?menu=open)

面板收起后，右上角留一块两行 HUD，第一行显示 Agent 状态，第二行显示待审数和打开键。HUD 入口从「Agent 运行中 · 待审 2 份」开始。按 `O` 回去处理一份再收起，计数会随之变为 1。在 HUD 状态也能用画布外的演示按钮看运行结束后的变化。[面板收起态](../mockups/gpt/hud.html)

| 键位 | 样稿行为 |
| --- | --- |
| `O` | 收起工作台或从 HUD 打开。输入框内保留字母输入。 |
| `Alt+1 / 2 / 3` | 对话、文件、审阅。 |
| `Tab`、`Shift+Tab`、`Enter`、空格 | 移动焦点、选择按钮或展开详情。确认框默认聚焦「返回」。 |
| 输入框内 `Enter` | 空闲时发送，运行时排队。中文输入法选词时由输入法处理。 |
| 编辑器内 `Ctrl+S` / `⌘S` | 保存为待审。离开有修改的编辑器会先询问。 |
| `Esc` | 依次退回当前弹窗、菜单、编辑或目录、对话，最后收起面板。 |

### 明度、交互与世界光照

- **表面与文字。** 从凹面到面板再到抬高的卡头，明度每次只变一小步。正文、说明、时间戳各有一档。1 px 分隔线只交代边界。按 WCAG 相对亮度公式核算，八套内置主题的正文与面板对比度为 **6.63–7.85∶1**，次级文字为 **5.25–6.27∶1**。
- **语义色。** 成功、警告、危险、信息先在 OKLCH 取绿色、赭黄、红、蓝四个色相。深色组从约 `L 0.77 / C 0.064` 起步，浅色组从约 `L 0.44 / C 0.062` 起步，再掺少量本主题强调色。失败同时用叉号和原因，差异同时用正负号和整行底色。内置增删行文字与各自底色的最低对比度为 **4.55∶1**。
- **悬停与按下。** 在原有底色上叠同色温薄层，按下比悬停多一档不透明度。选中使用稳定的微染底色和 1 px 标记。样稿的透明叠层过渡为 100 ms。MC 可以在每帧对起止 alpha 做线性插值，减少动态效果时直接切到终值。
- **世界浮层。** 深色主题给底板约 90% 不透明度，浅色主题约 93%。按 sRGB 分别与白昼亮底、全暗夜色的两个极值合成，浮层文字最小对比度为 **5.63∶1**。文字阴影只落一个像素。图标、边框、控件和建筑占位画都能用像素贴图、实色或半透明矩形实现。游戏内正文以约 9 px 为基准，页标题最大两倍。

### JSON 协议与 35 个颜色字段

页面上方并列显示八种主题的表面与强调色色块、名称以及当前选择，下方游戏顶栏的「外观」也可展开完整列表。每份 HTML 都内嵌相同的主题目录，双击可以离线切换。「载入主题 JSON」会采用文件中的默认主题。同 ID 覆盖内置项，新 ID 追加到列表。读错时保留当前选择。自定义主题数据在当前页面有效。[完整 themes.json](../mockups/gpt/themes.json)

顶层 `version` 为 `2`，`default` 为默认 ID，`themes` 为数组。每项有唯一 `id`、显示名 `name`、下表所列 35 个键组成的 `colors`。色值为 `#RRGGBB` 或 `#RRGGBBAA`，最后两位是 alpha。旧版 15 字段 JSON 也可载入，样稿保留原色并按面板明暗补齐新增角色。下表列出每个键实际绘制的位置。

| 字段 | 使用位置 |
| --- | --- |
| `backdrop`、`inset`、`panel`、`raised` | 分别用于画布外背景、顶栏和工具记录底、工作台主平面、消息卡头与菜单。 |
| `line` | 1 px 分隔线、卡片边线和工具子调用的缩进导线。 |
| `text`、`muted`、`faint` | 依次用于正文、次要说明或动作，以及时间戳、行号和选区尺寸。 |
| `accent`、`on-accent` | 当前标签、主按钮底色，以及主按钮上的字和图标。 |
| `hover`、`pressed`、`focus` | 悬停与按下叠层，以及键盘焦点线和输入焦点框。 |
| `input-bg`、`input-border` | 消息框和 TOML 编辑器的底与边。 |
| `selected`、`scrollbar` | 当前文件行、当前工具行或所选主题底色，以及滚动条滑块。 |
| `success`、`warning`、`danger`、`info` | 已应用文件、逐文件校验提示、丢弃确认、排队和操作反馈。 |
| `diff-add-bg`、`diff-add-text`、`diff-remove-bg`、`diff-remove-text` | 展开的 TOML 差异内，新增行和删除行各自的底色与文字。 |
| `tool-done`、`tool-running`、`tool-waiting`、`tool-failed` | 工具进度卡里的勾、执行箭头、等待框、失败叉和对应状态文字。 |
| `preview-add`、`preview-remove`、`preview-file` | 世界中的新增与移除标记和图例，以及当前文件的虚线框与标签边线。 |
| `overlay`、`on-overlay`、`text-shadow` | 世界上的预览开关、视角提示、标签与 HUD 的半透明底、文字及 1 px 文字阴影。 |
