# P2S 游戏内 Agent 界面「B+C 结合」布局与主题方案

## 1. 一句话定位：为什么是「B+C 结合」

现在的 `P2SChatScreen` 采用左（文件树 + TOML 编辑器）右（聊天面板）三栏并排。在 Minecraft 常见 GUI 逻辑分辨率 **640×360**（例如 1280×720 窗口下 GUI Scale = 2）下，三栏最小宽度相加已经超过 640px，结果就是**游戏里的 3D 建筑世界被彻底挡死**——玩家一边让 AI 盖房子，一边看不见预览长什么样。

与此同时，P2S 玩家的真实使用习惯是典型的 **Vibe Coding**：
- **95% 的时间在对话**：提需求、看进度、决定应用还是丢弃，边看右侧 3D 世界里的半透明虚影边沟通；
- **4% 的时间在审阅**：AI 一次改了 2～3 个工作区文件，需要切进去看清楚改了哪些方块、风险高不高，逐个点应用或丢弃；
- **1% 的时间才手改**：偶尔微调几行坐标或方块替换，平时根本不想盯着 TOML 代码看。

因此我们采用 **「B+C 结合」的单侧抽屉架构**：
- **B（对话为主）**：默认打开就是「对话」页，只占屏幕左侧约 **49%**（`312×348` MC 逻辑像素），**右侧超过一半的 3D 游戏世界完全敞开**；
- **C（IDE 顶栏标签）**：在同一个抽屉顶部用三个扁平标签 **`[对话]` / `[审阅 N]` / `[文件]`** 切换视图，审阅与文件编辑退居标签页与卡片直达入口，需要时点一下切过去，用完切回对话，不常驻抢占世界视野。

## 2. 信息架构（IA）与屏幕空间切分

在 **640×360** 逻辑像素下，整体划分为「左侧工作抽屉」与「右侧 3D 世界视口」两部分：

| 区域 | 宽 × 高（MC 逻辑像素） | 占比 | 说明 |
| --- | --- | --- | --- |
| 左侧抽屉 · 对话模式 | `312 × 348`（距边 `6px`） | 49% | 默认首页，聊天流 + 进度 + 排队 + 待审卡，右侧留出 `316px` 看建筑 |
| 左侧抽屉 · 审阅模式 | `368 × 348` | 57.5% | 略微展宽以完整展示 Diff 行号与坐标，右侧仍保留 `260px` 实时 3D 预览 |
| 左侧抽屉 · 文件模式 | `384 × 348` | 60% | 左侧窄文件树 `116px` + 右侧 TOML 编辑区 `268px`，右侧保留 `244px` 世界 |
| 收起态 · 仅看世界 | `148 × 20` 悬浮胶囊 | <3% | 点抽屉右上角 `«` 收起，只留左上角状态胶囊（显示运行态/待审数），98% 视野看建筑 |

### 抽屉顶部结构（固定 2 行，共 `38px` 逻辑像素）

1. **第一行（`18px`）：上下文与低频工具**
   - 左侧：**项目/会话合并选择器** `[江南庭院 · S4 ▾]` + 快速新建 `[+]`。把原本散落的「项目 / 会话 / 新建」三个按钮收进一个清晰下拉入口，点击弹出项目与会话切换浮层。
   - 右侧：低频但关键的操作收拢到一排图标按钮：`[↶ 撤销]`、`[↷ 重做]`、`[◆2 检查点]`、`[··· 更多]`（内含「压缩上下文」「检查点列表」「新建项目」）、`[⚙ 设置与主题]`、`[✕ 关闭]`。
2. **第二行（`20px`）：B+C 三大主标签 + 视图调节**
   - 左侧主标签：**`对话`** | **`审阅 3`**（有待审文件时亮出琥珀色数字徽标，为 0 时弱化） | **`文件`**。
   - 右侧调节钮：**`[◧]`** 宽/标准切换（临时拉宽或恢复标准宽度）、**`[«]`** 收起抽屉仅看世界。

### 为什么不把工具栏和输入区继续堆按钮？
原版 `P2SChatScreen` 聊天顶栏有两排按钮加检查点输入框，底部还有 `Ask` 和输入切换。新布局遵循两条原则：
- **状态驱动显隐**：`Ask` 选择卡只在 Agent 调用 `ask_user` 时出现；丢弃原因框只在点击「丢弃」后就地展开；计划进度条只在存在 `update_plan` 数据时显示；
- **信息分层**：高频动作放第一视野（输入、停止、应用/丢弃、切换审阅），低频维护动作归入 `[···]` 或 `[⚙]`，保持每个屏幕同屏按钮不超过 6～8 个。

## 3. 视图切换与双向联动

三个标签不是孤立的“三张静态页面”，而是围绕一次构建任务互相打通：

1. **对话 → 审阅（直达）**
   - 对话流末尾出现「待审汇总卡」时，点击某一行文件右侧的 **`[审阅]`**，直接切到 `审阅` 标签并定位到该文件；
   - 点击卡片底部的 **`[逐个审阅 (1/3) →]`**，自动切到 `审阅` 标签的第一个待审文件。
2. **审阅 → 对话（决策回流）**
   - 全部 3 个待审文件都执行「应用」或「丢弃」后，自动展示「全部处理完成，已通知 Agent」提示，一键或自动切回 `对话` 标签继续下一轮对话。
3. **审阅 → 文件（偶尔手改的真正入口）**
   - 审阅某文件时发现只有一两处数值想自己微调，可点标题栏的 **`[在文件中打开]`** 跳到 `文件` 标签；
   - **安全保护**：只要某个文件还挂着待审补丁（`hasPendingPatch = true`），在 `文件` 标签打开时会显示顶部只读锁条：**「此文件存在待审改动，已设为只读 · [去审阅处理]」**，避免玩家误改旧基准版本造成 `base_revision` 冲突。已应用的干净文件（如 `main_hall.toml`）则可直接编辑与保存。
4. **文件 → 对话（片段引用）**
   - 沿用并简化 P2S 现有的代码片段引用能力：在 `文件` 页选中几行 TOML 后，悬浮条只给一个清晰按钮 **`[+ 添加 L14-18 到下条对话上下文]`**，点击后在 `对话` 页输入框上方以紧凑 Chip 呈现。

## 4. 一个完整任务的端到端流程

以「玩家在江南庭院东侧补建一座带回廊的歇山顶木亭」为例：

1. **发起任务（`对话` 页）**
   - 玩家打开界面（快捷键 `O`），确认左上角项目 `[江南庭院 · S4]` 与右侧 3D 选区边框正确。
   - 在底部输入框敲一句话回车发送：`在选区东侧补建一座带回廊的歇山顶木亭，檐角用深色橡木，地面铺青石板。`
2. **运行中：进度、停止与排队追加（`对话` 页 · 对应效果图 `01-chat-running.html`）**
   - 顶栏下方出现 **Plan 进度条**（可折叠/展开）：显示 `执行中 2/4 · 正在计算屋脊几何曲线`，下方 4 步清晰标出已完成 `✓`、进行中 `●`、待办 `○`。
   - 对话流里每次工具调用生成 **紧凑工具折叠条**：`▸ 读取世界选区 18×12×18`、`▾ 运行脚本 geo.gable_roof · 420ms`（可点击展开参数与耗时）、`▸ 委派子代理 block-id-searcher`。当前正在流式输出思考/说明文字，结尾带像素光标。
   - 玩家突然想补充栏杆材质，直接在底部输入框打字回车：输入按钮在运行期间变为 **`[■ 停止]`**（或右侧显示 **`[排队 +]`**，输入非空时回车自动排队，输入框清空时也可点 `[■ 停止]` 立即中断运行与子代理）。
   - 排队消息不会乱插进正在滚动的对话流，而是固定停靠在输入框正上方：**`排队待发送 (1)："回廊栏杆改用云杉木栅栏，别忘了加挂灯笼" [编辑] [取消]`**，等当前工具批次结束后通过现有的 `steer` 机制自动喂给 Agent。
3. **生成 3 个待审文件（`对话` 页 · 对应效果图 `02-chat-pending.html`）**
   - Agent 完成规划与写入，Plan 进度条收拢为一行 `✓ 计划已完成 4/4`，`审阅` 标签出现琥珀色徽标 **`审阅 3`**。
   - 对话末尾出现一块干净的 **待审汇总卡**：
     - 标题行：`待审改动 · 3 个文件 · +318 / -24 方块 · 风险: 低`
     - 文件列表：
       1. `pavilion_roof.toml`（歇山顶双坡屋檐与角梁 · `+142 -6`）`[审阅]` `[应用]`
       2. `corridor_frame.toml`（回廊柱网与云杉木栏杆 · `+118 -10`）`[审阅]` `[应用]`
       3. `courtyard_floor.toml`（青石板地面与灯笼点缀 · `+58 -8`）`[审阅]` `[应用]`
     - 底部决策：`[逐个审阅 (1/3) →]`、`[全部应用 (3)]`、`[全部丢弃]`。
   - 此时右侧 3D 世界同步显示 3 个部位的半透明结构虚影预览，玩家先看一眼整体体量，如果满意可直接点 `[全部应用]`，想细看就点 `[逐个审阅]`。
4. **逐个审阅（`审阅` 页 · 对应效果图 `03-review-diff.html`）**
   - 进入 `审阅` 页，顶部展示 3 个待审文件切换胶囊，当前高亮 `1. pavilion_roof.toml ●`，右侧世界视口也会把当前聚焦的屋顶部分高亮、其余两层弱化，方便对照看 Diff 与实际位置。
   - 中间只展示有变更的 TOML 片段（前后保留 3 行上下文，未改部分折叠成 `··· 展开 12 行未修改内容 ···`），提供 `< 变更 1/3 >` 跳转按钮。
   - 底部固定决策条：**`[✓ 应用此文件]`**、**`[✕ 丢弃...]`**（点击后就地展开可选原因输入框，回车直接提交丢弃原因并切到下一文件）、**`[跳过 →]`** 与 **`[全部应用]`**。
5. **偶尔手改文件（`文件` 页 · 对应效果图 `04-files-editor.html`）**
   - 应用完想微调已有建筑 `main_hall.toml` 里某根柱子的材质或高度，点顶部 **`[文件]`** 标签进入。
   - 左侧文件树选 `main_hall.toml`，右侧直接出现带行号和柔和语法着色的 TOML 编辑器。改完点 **`[格式化]`** + **`[保存]`**（`Ctrl+S`），顶部实时提示基准修订号 `rev.4` 与保存状态。如果还想让 Agent 接着改某段，拖拽/Shift 选中几行，点一下浮动条直接把代码段送入对话上下文。

## 5. 窄屏降级方案（480×270 逻辑像素）

当窗口较窄或玩家调高了 MC GUI Scale（可用逻辑分辨率跌到 **480×270** 以下，例如设定断点 `< 560px`）时，绝不硬挤双栏，按以下四条规则降级：

1. **抽屉收窄但保底世界条**：对话/审阅/文件统一采用 `min(288, width - 160)` 宽度（在 480px 下抽屉占 `288px`，右侧保留 `180px` 世界预览）；同时保留 `[⤢]` 按钮，点一下可把抽屉临时撑满至 `464px` 专心看长 Diff。
2. **顶栏二级操作折叠**：第一行只留 `[江南庭院 · S4 ▾]` + `[···]` + `[✕]`，撤销/重做/检查点/压缩/设置全部收纳进 `[···]` 弹出菜单。
3. **文件模式取消左右分栏**：隐藏左侧 `116px` 常驻文件树，改为编辑区上方一行文件下拉条 `[📄 main_hall.toml ▾] [+新建] [管理]`，让编辑器保留完整宽度。
4. **审阅模式文件栏改为单行步进器**：多文件胶囊改为紧凑的一行 **`[‹] 1/3 pavilion_roof.toml ● [›]`**，把宝贵的垂直高度留给 Diff 正文与底部应用/丢弃按钮；并且随时可用 `[«]` 收起成 `140×20` 悬浮小条检查全屏建筑。

## 6. 键盘交互与 Esc 行为栈

为避免 MC 界面里常见的“按 Esc 想关提示条结果整个聊天界面没了”或“输入框抢焦点导致快捷键失效”问题，设计明确的分层按键规则：

### Esc 四层退避栈（每次按 Esc 只消解最顶层）
1. **第 1 层（临时内联状态）**：正在填丢弃原因 / 新建或重命名文件 / 切换项目浮层 / `[···]` 菜单 / `Ask` 自定义输入 → 按 `Esc` 关闭该浮层或取消当前临时输入，不离开当前标签。
2. **第 2 层（文本焦点与选区）**：
   - 若 `文件` 页 TOML 编辑器处于焦点且有行选区 → 第一次 `Esc` 清除选区，第二次 `Esc` 退出编辑器焦点；
   - 若聊天输入框或排队编辑处于焦点 → 退出输入框焦点（让快捷键如 `Ctrl+1/2/3`、滚轮浏览更顺手；若本来已失焦则进入下一层）。
3. **第 3 层（仅看世界折叠态）**：若当前处于 `[«]` 收起态 → 按 `Esc` 先关闭整个界面（或按设定返回游戏，见下节待拍板问题 #3）。
4. **第 4 层（退出界面）**：无任何浮层与编辑焦点时，按 `Esc` 退出 `P2SChatScreen` 回到 Minecraft 游戏画面，自动保留当前草稿与抽屉宽度/标签状态。

### 常用快捷键
- `Enter`（聊天框焦点）：空闲时发送消息；Agent 运行中自动进入排队队列（输入为空时点击发送钮为停止）。
- `Ctrl + 1 / 2 / 3`：快速切换 `对话` / `审阅` / `文件`。
- `Alt + ← / →`（审阅页）：切换上/下一个待审文件；`[ / ]` 在非输入状态下跳转上一处/下一处 Diff 变更。
- `Ctrl + S`（文件页）：保存当前 TOML 文件。
- `Ctrl + .`：停止当前正在运行的 Agent。

## 7. 独立 JSON 主题配置文件规范（与 CSS 变量一一对应）

主题做成独立 JSON 文件（例如存放在 `config/p2s_themes/<id>.json`），游戏内设置页可直接下拉切换、热刷新，无需重启 MC。

### 7.1 构色原则（克制、柔和、优雅）
- **禁止纯黑纯白**：深色底不用 `#000000`、亮文字不用 `#FFFFFF`，避免像素边缘产生刺眼眩光。
- **均匀微步表面层级**：`inset < canvas < surface < elevated < hover`，每级亮度差控制在 3%～6%，边界依靠表面反差与 1px 低存在感细线（`border-subtle`）分隔，不用厚重边框框住每个控件。
- **单主强调色 + 同温语义色**：每套主题只定义 1 个主强调色（`accent-primary`）；成功/警告/危险采用低饱和度莫兰迪/鼠尾草/暮玫瑰色调，与主底色冷暖一致，绝不出现高亮荧光绿或纯红撞色。

### 7.2 主题 JSON 格式与 CSS 变量映射表

颜色字符串统一采用 **`#RRGGBBAA`**（8 位十六进制，不透明为 `FF`，半透明面板如 `EB` ≈ 92% 不透明度）：
- 浏览器 CSS 引擎原生支持 `#RRGGBBAA`，**JSON 中 `colors` 对象的键名 `foo-bar` 直接一一对应 CSS 变量 `--foo-bar`**；
- Minecraft Java 端加载时只需把 `#RRGGBBAA` 转成 `0xAARRGGBB` 整数即可直接传给 `GuiGraphics.fill(...)` 与 `drawString(...)`。

### 7.3 随附的三套主题预览
在配套 HTML 效果图中均已内置实时切换与 JSON 查看器：
1. **Slate Mist（冷灰青 · 默认）**：冷调石板深灰 + 雾蓝单主色，适合全天绝大多数建筑场景，视觉最沉稳；
2. **Rosé Dusk（暮玫瑰）**：微暖暮紫灰 + 柔玫瑰粉灰强调（Rosé Pine 气韵），夜间或灯笼/木构建筑下格外柔和温润；
3. **Warm Stone（暖石灰 · 浅色）**：低反光暖羊皮石色（`#EAE6DF`）+ 深炭灰字 + 靛蓝强调，适合白天高亮度场景或偏爱浅色编辑器的玩家。

## 8. 需要用户拍板的问题

以下 5 个决策会直接影响后续 Java 落地实现，请拍板：

1. **抽屉默认停靠在左侧还是右侧？**
   - *方案 A（本稿采用，推荐）*：抽屉停靠在 **左侧**，右侧留给 3D 世界与 MC 准星视野；优点是符合“左文件/控制、右画布”的 IDE 直觉，且不会挡住右手手持工具动画。
   - *方案 B*：停靠在右侧（沿用原版聊天的右侧习惯）。是否保留配置项让玩家自选左右？
2. **在 `审阅` / `文件` 标签按 `Esc` 的期望行为是什么？**
