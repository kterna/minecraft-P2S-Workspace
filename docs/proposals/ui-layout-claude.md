# 聊天面板新布局（Claude 方案）：对话为主 + 标签切换

状态：设计稿，未改代码。效果图在 `docs/mockups/claude/`，用浏览器直接打开，页面顶部可以切换主题。
依据：本分支的 `P2SChatScreen`、`P2SChatSessionWidgets`、`P2SConfigScreen` 现状，以及 `ui-polish.md` 第 0～5 节的问题清单。

---

## 1. 一句话思路

把 `O` 面板做成 **“Agent 工作台”**：打开就是对话，Agent 在干什么、改了哪些文件、要你审什么，都在对话里能看到。
“审阅”和“文件”是两个标签页，需要时切过去，用完回到对话。
这就像用 VS Code 跑 Codex 或 Claude：大部分时间盯着 Agent 的终端，偶尔点开一个文件看看。

和现在最大的不同有三点：
1. **一个面板代替三栏。** 现在的“资源管理器 / 编辑器 / 会话”三栏改成一个左侧面板，右边整块留给游戏世界，方便边看预览边审。
2. **输入框常驻。** 不管在哪个标签，底部输入框都在，随时能对 Agent 说话。在审阅页说的话会自动带上“当前文件”。
3. **运行状态单独占一条。** “停止”按钮固定放在运行条上，发送键永远是发送，不再变身成 `■`。

## 2. 信息架构

### 2.1 面板的五层（从上到下）

```
┌───────────────────────────────────────┐
│ ◆ 北岸城堡 ▾  · 会话 12 ▾      ↶ ↷ ⋯ ⚙ │ 标题栏 18px
├───────────────────────────────────────┤
│ 对话 │ 审阅 3 │ 文件 │                  │ 标签栏 16px
├───────────────────────────────────────┤
│                                       │
│            内容区（随标签变化）          │
│                                       │
├───────────────────────────────────────┤
│ ◐ 正在编辑 walls/north.toml · 0:42 [停止]│ 运行条 14px（只在运行时出现）
├───────────────────────────────────────┤
│ 告诉 Agent 要做什么…            [发送] │ 输入框 32px（常驻）
└───────────────────────────────────────┘
          面板宽度约 54%，右边是游戏世界
```

- **标题栏**：项目名和会话名都是下拉按钮，代替现在的“项目”“会话”两个按钮；右边依次是撤销、重做、`⋯` 菜单、设置。
- **标签栏**：三个标签。“审阅”上的数字是待审文件数，为 0 时不显示数字。切到其他标签时，如果 Agent 正在运行，标签栏右侧会显示一个小的“◐ 运行中”。
- **运行条**：显示转圈、当前步骤、耗时、排队条数和“停止”按钮。空闲时不占高度。
- **输入框**：两行高，Enter 发送，Shift+Enter 换行。Agent 运行中发送的消息进入排队。

### 2.2 三个标签各放什么

| 标签 | 内容 | 对应现在的哪些东西 |
|---|---|---|
| 对话 | 消息流；“工作卡”（Agent 每一轮的工具步骤，可折叠）；思考过程（折叠，只显示字数）；子任务进度；待审卡片；选择题卡片；排队中的消息 | 现在的消息区、工具日志、choice 弹窗、Info 浮层里的计划与待应用补丁 |
| 审阅 | 左边是待审文件列表，右边是所选文件的差异；Agent 对这个文件的说明；应用、丢弃、上一个、下一个 | 现在左侧编辑区的 Diff 模式和应用/丢弃按钮 |
| 文件 | 左边是文件树，右边是只读正文；“编辑”按钮进入手改模式；新建、改名、删除放在文件树底部 | 现在的资源管理器和 Script 编辑器 |

### 2.3 现有按钮搬到哪里

| 现在 | 新位置 |
|---|---|
| 项目、会话 | 标题栏下拉 |
| 新建会话、压缩、检查点（存点/列表）、结构摘要、导出诊断 | `⋯` 菜单 |
| 撤销、重做 | 标题栏图标 `↶ ↷` |
| 配置 | 标题栏 `⚙` |
| Info 浮层 `[i]` | 取消。计划放进工作卡顶部；待应用补丁变成待审卡片；结构摘要和检查点进 `⋯` |
| 选择题弹窗 | 对话里的卡片，就在输入框上方，选项是整行按钮 |
| “附带上下文”列表（左下角固定 110px） | 输入框里的引用小标签，例如 `@roof.toml:12-20`，点 × 去掉 |
| 获取 / 保存 / 格式化 / 清空 | 文件页编辑模式的工具条 |
| 三个折叠按钮和两条拖动分隔线 | 只保留面板右边缘一条拖动线；`O` 关闭面板 |

## 3. 一个完整任务怎么走

对应效果图：`01` → `02` → `03` →（可选）`04`，面板关上时看 `06`。

1. **发起。** 按 `O` 打开，默认停在“对话”。输入“把北墙加高到 12 格，加箭孔，屋顶改深色橡木坡顶”，按 Enter。
2. **Agent 运行（`01-chat-running.html`）。**
   - 对话里出现一张工作卡，每完成一步加一行：“✓ 读取 walls/north.toml”“✓ 脚本 生成箭孔 · 12 次调用 · 1 失败”。正在执行的一步高亮，并带转圈。
   - 脚本这一行点开，能看到子调用汇总、失败原因和输出（数据结果里本来就有，见 `ui-polish.md` 第 2 节）。
   - 子任务（子 Agent）在工作卡里缩进显示，有自己的步数和耗时。
   - 思考过程默认折叠成“▸ 思考 1,240 字”，点开才显示全文。
   - 这时候想补一句，照常输入发送：消息以虚线框的“待送达”形式挂在对话末尾，送达前可以撤回。
   - 运行条上一直有“停止”。点了以后显示“正在停止…”，结束后在工作卡末尾写“已停止，已发往服务端的操作可能已生效，可用撤销回退”。
   - 世界里同步显示预览方块（半透明绿色是新增，红框是要拆掉的）。
3. **结束，出现待审卡片（`02-chat-review-card.html`）。**
   - 工作卡自动折叠成一行：“▸ 已完成 · 9 步 · 1:18”。
   - 下面是 Agent 的总结，再下面是待审卡片：3 个文件，每个文件显示新增和移除的方块数、风险等级和“查看”按钮。
   - 卡片底部有三个按钮：**逐个审阅**（主按钮）、全部应用、全部丢弃。
   - “审阅”标签上出现数字 3。
4. **逐个审阅（`03-review.html`）。**
   - 点“逐个审阅”或某个文件的“查看”，切到审阅页并选中对应文件。
   - 右边显示差异，上方是 Agent 对这个文件的一句说明，用 `◀ ▶` 在几处改动之间跳。
   - 世界里只高亮当前文件的预览，其他文件变暗（需要预览渲染支持，见第 8 节问题 6）。
   - 点“应用”后列表里这一项打勾，自动跳到下一个；点“丢弃”会在按钮行原地出现一个原因输入框（可留空）。
   - 有不满意的地方，直接在底部输入框里说“箭孔再密一点”，消息会自动带上当前文件，Agent 修改后列表刷新。
   - 全部处理完后自动回到“对话”，对话里留一条记录：“已应用 2 个，丢弃 1 个”。
5. **偶尔手改文件（`04-files.html`）。**
   - 在文件页选中文件，默认只读。点“编辑”进入编辑模式，出现保存、取消、格式化，标题旁显示“● 未保存”。
   - 如果这个文件还有待审改动，正文上方会出现提示条“此文件有待审改动，先去审阅”，这时编辑按钮不可用，避免两份改动打架。
   - 选中几行后点“引用到对话”，输入框里就多一个 `@roof.toml:12-20` 标签。
6. **关上面板继续玩（`06-hud.html`）。** 按 `O` 或 Esc 关闭面板，Agent 继续在后台运行。屏幕右上角有一个小提示：“◐ Agent 运行中 0:42 · 待审 3 · O 打开”。

## 4. 视图切换规则

- **点击标签**，或按 `Ctrl+1`（对话）、`Ctrl+2`（审阅）、`Ctrl+3`（文件）。
- **自动跳转只发生在你主动点了按钮之后**，例如点“逐个审阅”“查看”“去审阅”。Agent 运行中不会自己把你切走。
- **审阅全部处理完后回到对话**，这是唯一一次自动切换，因为审阅页已经空了。
- **面板关闭后再打开**，停在上次的标签；如果期间出现了新的待审文件，依然停在原标签，只在“审阅”上亮数字。
- 各标签的滚动位置、选中文件、折叠状态，在本次游戏期间都保留（沿用现在的 `retainedDockLayout` 做法，`P2SChatScreen.java:33`）。

## 5. 窄屏怎么降级

所有尺寸都按 MC 的 GUI 逻辑像素算（窗口像素 ÷ GUI 缩放）。

| 逻辑宽度 | 典型情况 | 面板 | 其他变化 |
|---|---|---|---|
| ≥ 560 | 1080p 缩放 2～3 | 宽度 = 主题里的 `panelWidth` 比例，最小 300 | 标准布局 |
| 400～559 | 1080p 缩放 4（480×270） | 固定 300 宽，世界露出右侧一条 | 标题栏和标签栏合成一行；工作卡只显示当前步骤和“+N 步”；审阅页的文件列表收成顶部一行下拉；输入框变单行 |
| < 400 | 很小的窗口 | 占满全屏，不露世界 | 同上；另外 `⋯` 菜单吸收撤销、重做 |

逻辑高度小于 300 时还会：输入框只留一行，隐藏快捷键提示，工作卡最多展开 4 行。
效果图 `05-narrow.html` 就是 480×270 的情况。

## 6. 键盘和 Esc

**Esc 从里往外一层层退，每次只退一层：**

1. 关掉打开的下拉菜单或 `⋯` 菜单；
2. 退出丢弃原因输入、重命名输入；
3. 退出文件编辑模式（有未保存改动时，第一次 Esc 只提示“再按一次放弃修改”）；
4. 如果输入框里有字，先让输入框失去焦点（文字保留）；
5. 关闭面板。

**Esc 永远不会停止 Agent**，停止只能点“停止”或按 `Ctrl+.`，避免想关面板时误停。

| 按键 | 作用 | 生效范围 |
|---|---|---|
| Enter / Shift+Enter | 发送 / 换行 | 输入框 |
| Ctrl+1 / 2 / 3 | 切到对话 / 审阅 / 文件 | 全局 |
| Ctrl+. | 停止 Agent | 运行时 |
| A / D | 应用 / 丢弃当前文件 | 审阅页，焦点不在输入框时 |
| Shift+A | 全部应用（会再确认一次） | 审阅页 |
| J / K 或 ← / → | 下一个 / 上一个文件 | 审阅页 |
| N / P | 下一处 / 上一处改动 | 审阅页 |
| E | 进入编辑 | 文件页 |
| Ctrl+S | 保存 | 文件编辑模式 |
| Tab | 在列表、正文、输入框之间移动焦点 | 全局 |
| ↑（输入框为空时） | 取回上一条发送的消息 | 输入框 |

所有按钮的悬停提示都写上对应快捷键，例如“应用（A）”。

## 7. 主题配置文件

### 7.1 放在哪里、怎么切换

- **内置主题** 打包在模组里：`assets/prompt2structure/p2s_themes/<id>.json`，只读。首批三套：`midnight`（深夜，默认）、`contrast`（高对比）、`stone`（原版石板）。
- **用户主题** 放在 `config/p2s_themes/<id>.json`。和内置主题同 id 时，用户文件优先。
- **当前主题** 记在 `config/p2s_client.json` 的 `"theme": "midnight"` 字段里。
- **切换方式：**
  - 配置页新增“外观”标签：下拉选择主题，旁边有“重新载入”和“打开主题文件夹”两个按钮。
  - 每次打开 `O` 面板时检查主题文件的修改时间，变了就自动重载。改完 JSON 关掉面板再打开就能看到效果，不用重启游戏。
- 效果图里的主题按钮切换的就是这三份 JSON（页面里点“查看主题 JSON”可以看到原文），**CSS 变量名和 JSON 字段名一一对应**：每个颜色字段对应同名的 `--字段名`；尺寸字段里 `pad`、`lineHeight`、`textShadow`、`buttonTextShadow` 也同名，`panelWidth` 和 `minPanelWidth` 合起来算出面板宽度 `--panelW`（和游戏里的算法一样）。

### 7.2 文件格式

```json
{
  "schema": 1,
  "id": "my-theme",
  "name": "我的主题",
  "extends": "midnight",
  "colors": {
    "panelBg": "#0B111BE6",
    "accent": "#62B6F2"
  },
  "metrics": {
    "panelWidth": 0.54,
    "minPanelWidth": 300,
    "pad": 6,
    "lineHeight": 10,
    "textShadow": true,
    "buttonTextShadow": true
  }
}
```

- 颜色写成 `#RRGGBB` 或 `#RRGGBBAA`（最后两位是不透明度），加载时转换成 MC 用的 ARGB 整数。
- `extends` 可选，表示“没写的字段从哪个主题继承”。所以自己做主题时只写想改的几个字段就行。
- 未知字段会被忽略，方便以后加字段时旧文件还能用。

### 7.3 颜色字段

| 分组 | 字段 | 用在哪里 |
|---|---|---|
| 面板 | `panelBg` `panelEdge` `headerBg` `runBarBg` | 面板底色、右边缘线、标题栏、运行条 |
| 标签 | `tabBarBg` `tabActiveBg` `tabText` `tabTextActive` | 标签栏 |
| 层次 | `surface` `surfaceHi` `border` `divider` `selection` | 卡片、高亮行、边框、分隔线、选中文本 |
| 文字 | `text` `textMuted` `textDim` | 正文、次要文字、最弱提示 |
| 强调 | `accent` `accentText` | 强调色，以及强调色底上的文字 |
| 对话 | `userBubble` `userBorder` `userText` `assistantText` `toolVerb` `thinkingText` | 用户气泡、AI 正文、工具动词、思考文字 |
| 状态 | `ok` `warn` `danger` `pending` `pendingBg` | 成功、警告、失败、待审及其底色 |
| 差异 | `diffAddBg` `diffAddText` `diffDelBg` `diffDelText` `gutterText` | 差异视图和行号 |
| 输入 | `inputBg` `inputText` `inputBorder` `inputBorderFocus` `placeholder` `caret` | 输入框 |
| 按钮 | `buttonBg` `buttonBorder` `buttonText` `primaryBg` `primaryBorder` `primaryText` `dangerBg` `dangerBorder` `dangerText` `bevelHi` `bevelLo` | 普通、主要、危险按钮；`bevel*` 是按钮左上和右下 1px 的亮边和暗边，原版石头按钮靠它出立体感，不想要就设成全透明 |
| 角标 | `badgeBg` `badgeText` | “审阅 3”的数字 |
| 语法 | `synKey` `synString` `synNumber` `synSection` `synComment` | 文件正文的 TOML 着色 |
| HUD | `hudBg` `hudText` | 面板关闭时右上角的小提示 |

### 7.4 尺寸字段

| 字段 | 默认 | 范围 | 说明 |
|---|---|---|---|
| `panelWidth` | 0.54 | 0.35～0.8 | 面板占屏幕宽度的比例 |
| `minPanelWidth` | 300 | 240～480 | 最小宽度（逻辑像素） |
| `pad` | 6 | 2～12 | 面板内边距 |
| `lineHeight` | 10 | 9～14 | 正文行高。MC 字体本身 9 |
| `textShadow` | true | — | 面板文字是否带 MC 式阴影 |
| `buttonTextShadow` | true | — | 按钮文字是否带阴影 |

超出范围的值会被夹到范围内，并在日志里警告一次。

### 7.5 坏文件怎么处理

原则：**主题出错绝不能让面板打不开或游戏崩溃。**

| 情况 | 处理 |
|---|---|
| JSON 语法错误 | 跳过这个文件，继续用上一次成功加载的主题；面板打开时在标题栏下方弹一条提示：“主题 my-theme.json 第 12 行有错，已使用 深夜”，5 秒后消失；日志里记完整错误 |
| 某个颜色写错（如 `"#GG0000"`） | 只有这个字段回退到继承值，其余照用；日志警告一次 |
| 缺字段 | 按 `extends` 链继承，链的末端永远是内置的 `midnight` |
| `extends` 指向不存在的主题，或者互相继承成环 | 直接以 `midnight` 为父主题，日志警告 |
| `"theme"` 指向的主题不存在 | 用 `midnight`，配置页的下拉框显示“（未找到：xxx）” |
| `schema` 比模组支持的新 | 照常尽量加载，提示“主题版本较新，部分效果可能不生效” |

可选的检查：加载时计算 `text` 与 `panelBg` 的对比度，过低时在配置页的预览旁提示“文字可能看不清”（只提示，不拦截）。

### 7.6 代码上怎么接

新增一个只放数据的 `P2STheme`（颜色全部是 int、尺寸是 int 或 float）和一个 `P2SThemeLoader`。所有绘制代码改成读 `P2STheme.current().xxx`，不再直接写十六进制数字。这一步本身就能解决 `ui-polish.md` 1.3-B 和 1.3-C 里的问题，可以先于新布局单独做。

## 8. 需要你拍板的问题

1. **面板放左边还是右边？** 效果图放在左边（阅读顺序从左到右，也像 IDE 的侧栏）。现在的会话面板在右边，换边需要重新适应。也可以做成配置项。
2. **默认主题用哪套？** 效果图提供深夜、高对比、原版石板三套。我推荐深夜作为默认。
3. **停止的快捷键用 `Ctrl+.` 可以吗？** Esc 被设计成永远不会停止 Agent。
4. **“全部应用”要不要二次确认？** 方案里在审阅页按 Shift+A 要确认，卡片上的“全部应用”按钮直接执行（可以撤销）。
5. **思考过程默认折叠只显示字数，可以吗？** 要不要存进会话记录？
6. **审阅时世界里只高亮当前文件**：这需要改预览渲染，工作量不小。不做的话就是所有待审改动一起显示。
7. **文件页的“编辑”要不要藏得更深？** 例如放进 `⋯`，或者在配置里打开“显示手动编辑”之后才出现。
8. **面板关闭后的右上角提示**：默认开还是关？
9. **窄屏（缩放 4 档）时让面板占满全屏，还是保留右侧一条世界？** 效果图保留了 180px 的世界。
10. **排队消息允许撤回吗？** 这需要改运行时，不只是界面。
